# けふのティータイム

本編/自由行動で扱う「時代を超える根源的な業」と、サイトで継続更新する「現代的・時事的な悩み」は分ける。

本編の自由行動で選べる分母は、既に設計済みの根源的な業テーマを正本にする。現代的な問いは混ぜず、サイト側の `004 / けふのティータイム` として扱う。

## 役割

けふのティータイムは、固定客を作るための継続更新枠。

- ユーザーから募った悩みを扱う。
- **恋愛相談を多めに作る**（kako-jun 方針 2026-09-06）。恋愛は最も一般的で普遍的な興味であり、生々しい感情を打ち明けられる「王様の耳はロバの耳」の穴になることを狙う。打ち明けた人を裁かず、安い共感でも説教でもなく、思考の道具を返す。
- 1つの問いについて、3人の住人による対談/情報交換形式を基本にする。
- せおは中心の聞き役として、問いを整理し、住人同士の視点の違いを引き出す。
- 全住人に必ず答えさせず、テーマごとに映える3人を選ぶ。
- 必要なら、対談内の1人分の発言をショート動画用に切り出せるようにする。
- 本編の普遍性を壊さず、サイト側の更新性を担う。

## 待機列を公開する理由

扱う予定のテーマ待機列は、サイト上で公開する。

待機列は単なる内部 TODO ではない。

- ユーザーが今後の更新を見てワクワクできる。
- テーマ募集時の参考例になる。
- ユーザーが自分の悩みを投稿するときの例文として機能する。
- 「このサイトはこういう悩みを扱ってくれる」という期待値を作る。
- 投票/人気順/採用予定と組み合わせることで、再訪する理由になる。

本編の業テーマのような短い一語ではなく、ある程度長い悩み相談の質問文形式にする。

公開時は、原案の切実さは残しつつ、煽り・断定・特定集団攻撃に見えすぎる表現は少し中立化する。**相談文の固有名詞（作品名・商品名など）は残す**＝正直な質問になる（kako-jun 2026-09-06）。**回答（住人の台詞）では普遍化し、固有名詞を出さない**。

## 質問文化前の間引きルール

時事ネタはそのまま増やさず、質問文形式に整える前に既存の業テーマとの重複を判定する。

1. 候補ごとに、根っこの業へ写像する。例: 炎上で反論したい=論破/怒り、他人の成功がつらい=嫉み、AIに仕事を奪われるのが怖い=不安/焦り/意味。
2. 既存の業で十分扱えるものは、けふのティータイムの新規話題として増やさない。既存業への入口文に回すか、待機列から落とす。
3. 残すのは、AI、SNS、推し活、匿名コミュニティ、国際情勢など、現代的な表面や文脈がサイト導線として強いもの。
4. 判定表には `candidate / question_text / core_theme / decision(keep|merge|drop) / reason` を持つ。
5. 業と根が重なる場合でも、対談形式にすることで本編/自由行動と演出を変えられるかを確認する。変えられないなら作らない。

## 対談プロット

けふのティータイムは、採用時点で3人の選び方と分担まで先に決める。単独回答を3本並べるのではなく、時代を超えた哲人同士のやり取りをシミュレーションする。

- 住人A: 問いを切り分ける役。前提や言葉の混線をほどく。
- 住人B: 別の軸を持ち込む役。Aだけでは見えない価値・制度・身体・感情などを出す。
- 住人C: 現代への接続役。ユーザーが明日どう考えるかへ落とす。
- せお: 聞き役。問いを要約し、住人同士の差を確認し、結論を急がせない。

けんかや論破合戦にはしない。視点の違いは出すが、相手を潰すのでなく、問いを立体化するための対話にする。感情的になるのは、ちょっとだけにとどめる（語気を強める程度・相手を否定しない）。

- せお／ヴィンチアは対談の必須要員ではない。特別扱いせず、住人と同格の1人として参加してよい回もある。せお・ヴィンチアを入れない回は、聞き役不在のぶん3住人がそのまま視点をぶつけ合う（例: 第一弾「大会の悔しさ」）。
- サイトの参加者表示は `src/data/teaTimeSpeakers.ts` が住人8人＋せお／ヴィンチアを解決する（顔は `theo/bust.webp` `vincia/bust.webp`、ラベルは主人公／司会）。テストも同じ集合で判定する（2026-09-07 #9 temperature で初適用）。
- せお1人を説得して終わる自由行動のセルとは尺の作りが違う。3人がそれぞれの軸で話すぶん、多少長めになってよい。
- 平坦に進めない。中盤で急展開・どんでん返し・「終わったと思ったところからの延長」のどれかを最低1つ入れ、退屈させない。
- 結論はいちおう出す。なるべくポジティブに着地させる（3人の結論を1つに丸めなくてよいが、後味は前向きにする）。
- **相談者に都合の良い結論にも、制作側の見立てに合わせた結論にも寄せない**。各住人が自分の思想の立場から本気で検討し、「どうすべきか」を哲学的に答える（kako-jun 2026-09-06）。
- **立ち絵は全員「右」固定・かわりばんこ**（2026-07-16 実機で kako-jun 確定）。3人を左右中央に同時表示すると窮屈で、誰が喋っているか分からない。name-name の「1位置1キャラ」で同じ右に次の人を出せば前の人が自動退場するので、**画面には常に喋っている1人だけ**が立つ。冒頭に `[登場:]` を3人並べない（最初の話者1人だけ登場させる）。
- **末尾に `[選択]`（`→ hub` の圏外ジャンプ）を置く**。埋め込みは confinement 圏外ジャンプで終劇（story-ended）を発火し、サイト索引側は `data-slug` ＋ `ReadMarks` で完読マークを反映する（自由行動セルと同じ仕組み）。最後をイベント絵で閉じる回も同じで、`[イベント絵終了]` を書かずに `→ hub` へ進ませる。name-name は終劇時、イベント絵を消す前に黒フェードで覆う。
- **行頭の余韻横棒 `--`（前の話者を受ける書き出し）はそのまま書いてよい**。先頭 `──` が余分なクリック待ちを作るのは name-name 側のバグ（#421）で、脚本から消す対症療法はしない（原稿が正本）。

各ネタの制作前に、最低限この形でプロットを作る。

```text
topic:
question_text:
core_theme:
decision: keep|merge|drop
reason:
participants:
  - resident:
    role:
    facet:
    contrast_with:
  - resident:
    role:
    facet:
    contrast_with:
  - resident:
    role:
    facet:
    contrast_with:
seo_role:
conversation_arc:
short_video_cut:
```

## 制作前チェックリスト

ティータイムを作る前に、必ずこのファイルを読む。Codex/Claude で追加する場合は freeza の `/theo-hayami-write tea-time ...` を入口にする。イベント絵や自由行動セルとは制作規約が違うため、話題名だけを見て脚本を起こさない。

- 1話題につき3人を選び、A/B/Cの分担を先に決める。
- **形式は三段: ①冒頭でお便り（相談文）を紹介する → ②結論が出るまでは3人が互いに話す（読者に呼びかけない） → ③結論が出たら、それを読者に呼びかける**（2026-09-06 kako-jun 指摘。既存8本がこの型）。司会役が自分の疑問を立てて他の2人がそれに答える形にしない。中盤で相談者に呼びかけ続けるのも違反（呼びかけすぎ）。相談文の出し方（読み上げ・言い換え・相談者の情景）は回ごとに変えてよいが、提示自体は必須。
- 主人公の表記は脚本本文でもカタカナ「セオ」。「せお」は docs の説明用で本文に書かない。
- 単独回答を3本並べず、相手の発言を受けて問いを立体化する。
- けんか、論破合戦、相手を潰す会話にしない。感情的な強さは語気の範囲に留める。
- 中盤に急展開、どんでん返し、終わったと思ったところからの延長のどれかを置く。
- 結論を出し、後味は前向きにする。3人の意見を無理に一つへ丸めなくてよい。
- name-name では冒頭に3人を並べない。最初の話者1人だけを `[登場: ... 右]` で出し、以後も話者は右固定にする。
- 末尾に `[選択]` と `→ hub` を置き、既読が付く形で終える。
- 通常脚本と同じく、キャラ別の一人称・二人称は `docs/02_characters/character_bible.md` に従う。例: カンティアは `君`、ヴィンチアは `僕/きみ`、`お前` はデカリス専用。
- 時事枠なので、公開済み一覧は新しい話題ほど上に置く。ただし通番は公開時固定で、表示位置から再計算しない。新規話題を上に追加しても既存話題の番号は変えない。
- 公開済みティータイムは個別URLを持つため、ビルド時に `scripts/check-sitemap.mjs` で sitemap 掲載を検査する。`dist/tea-time/*/index.html` に生成されたページが `sitemap-*.xml` へ載らなければ `npm run build` を失敗させる。

## 置き場所案

本編:

```text
content/scripts/free/<業>__<住人>.md
content/scripts/main/*.md
```

けふのティータイム:

```text
content/scripts/current/<topic>__<住人>.md
```

未公開ストック:

```text
content/scripts/current-drafts/<topic>.md
```

`current-drafts/` はマージ待ち・公開待ち原稿の置き場。`src/data/teaTime.ts` に登録しない限り、一覧にも個別URLにも出さない。公開時は対象ファイルを `content/scripts/current/` へ移し、`publishedTeaTimeQuestions` に `number` / `publishedAt` / `sceneId` / `residents` を追加する。

またはサイト側だけで管理:

```text
content/site/current-questions/<topic>/<住人>.md
```

## 運用

- 本編自由行動の分母には混ぜない。
- サイトの `004 / けふのティータイム` として扱う。
- 人気投票/投稿募集で上位のものから制作してよい。
- 質問文は長すぎず、ショート動画にも切り出しやすく整える。
- 採用済み/制作中/待機中が見えるようにする。
